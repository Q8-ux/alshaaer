# دليل الجودة والتشغيل — أنت الشاعر

## الرؤية والنطاق

يحوّل التطبيق قصة مكتوبة أو تسجيلًا صوتيًا إلى قصيدة نبطية مخصّصة. يسبق إنشاء القصيدة فهم القصة، ثم أسئلة قصيرة تضبط المناسبة والنبرة والتفاصيل، مع حفظ النتائج في أرشيف المستخدم المسجّل.

يشمل النطاق الحالي: تجربة الزائر المؤقت، الحسابات، التحليل، التفضيلات، إنشاء القصيدة، التسجيل الصوتي، الأرشيف، ولوحة الإدارة. ولا تشمل الواجهة الثابتة على GitHub Pages تشغيل الذكاء الاصطناعي أو قاعدة البيانات.

## المستخدمون والتدفقات

- الزائر: يكتب القصة أو يسجلها، ويتابع التسلسل، وتُحفظ مسودته محليًا على جهازه.
- المستخدم المسجّل: ينفّذ التدفق نفسه مع أرشفة قصصه وقصائده في حسابه.
- المشرف: يدير المستخدمين وإعدادات التكامل من لوحة محمية.

التدفق الأساسي: قصة ← فهم وتحليل ← اختيارات المستخدم ← قصيدة ← أرشفة.

## المعمارية والبيانات

- Cloudflare Worker لتشغيل الواجهة ومسارات API.
- D1 للبيانات المنظمة، مع ربط كل سجل بمالكه.
- R2 للتسجيلات الصوتية، مع إبقاء المفاتيح والأسرار في بيئة التشغيل.
- حالات الطلب متتابعة وقابلة للتتبع: `received` ثم `analyzed` ثم `completed` أو `failed`.
- المسودة المحلية مرتبطة بهوية المستخدم على الجهاز، وتنتهي بعد 30 يومًا، ولا تتضمن الملف الصوتي الخام.

## تجربة الاستخدام

- يظهر تقدم واضح عبر القصة والفهم والاختيارات والقصيدة.
- تُستعاد المسودة بعد تحديث الصفحة أو انقطاع الشبكة.
- يؤدي تعديل القصة بعد تحليلها إلى إلغاء التحليل القديم، لمنع إنشاء قصيدة من سياق غير متطابق.
- يحافظ انتهاء مهلة الاتصال على محتوى المستخدم ويعرض رسالة قابلة للتنفيذ.

## ضوابط القبول

- لا يبدأ التحليل قبل بلوغ القصة الحد الأدنى المطلوب.
- لا تُنشأ القصيدة قبل اكتمال التحليل والاختيارات.
- لا يُستخدم تحليل قديم بعد تعديل القصة.
- تعكس قاعدة البيانات حالات الطلب وتربطها بالمستخدم الصحيح.
- تعرض `/api/health` جاهزية قاعدة البيانات والتخزين ومفاتيح التشغيل دون كشف أي سر.
- تضيف الاستجابات ترويسات منع الاستضافة داخل إطار، ومنع تخمين نوع المحتوى، وسياسة إحالة محدودة.

## فحوص ما قبل النشر

1. تشغيل `npm ci` ثم `npm test`.
2. التأكد من نجاح بناء Worker والتحقق من الملفات الناتجة.
3. التحقق من أسرار Cloudflare وربط D1 وR2 قبل تفعيل النشر.
4. استدعاء `/api/health` بعد النشر والتأكد من أن الحالة `ready`.
5. تجربة القصة النصية، التسجيل الصوتي، تعديل القصة بعد التحليل، استعادة المسودة، والأرشيف.

## التشغيل والتحسين المستمر

- راقب فشل مسارات التحليل والقصيدة وزمن الاستجابة، دون تسجيل محتوى القصص أو الأسرار.
- تعامل مع حالة `degraded` في فحص الصحة كإشارة لغياب ربط أو سر مطلوب.
- راجع أخطاء المستخدمين المتكررة قبل توسيع الخصائص، وأضف اختبارًا لكل إصلاح جوهري.
